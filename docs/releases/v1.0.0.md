## 1. Executive Summary

The **Home Intelligence Platform v1.0.0** marks the public portfolio release of an industrial-grade, TypeScript-first digital twin, predictive machine learning, and closed-loop automation platform for residential environments.

Over 10 discrete engineering phases, the platform has evolved from a clean relational telemetry schema to a comprehensive 12-stage autonomous control loop:

$$\mathbf{Sense \longrightarrow Ingest \longrightarrow Validate \longrightarrow Detect \longrightarrow Correlate \longrightarrow Predict \longrightarrow Anticipate \longrightarrow Decide \longrightarrow Interlock \longrightarrow Act \longrightarrow Verify \longrightarrow Audit}$$

## 2. Key Capabilities & Architectural Highlights

### Multi-Horizon Machine Learning (-28.1% RMSE)
- In-process Gradient Boosted Decision Trees (GBDT) and Random Forest models.
- Predicts $15\text{m}, 1\text{h}, 4\text{h}, 24\text{h}$ horizons with an average inference latency under **9 ms**.
- Circuit-breaker automatic fallback to statistical harmonic baselines if latency exceeds 800 ms.

### Cross-Sensor Incident Corroboration (0.00% Baseline FP)
- Temporal sliding-window multi-channel correlation.
- Eliminates false positives by requiring simultaneous physical multi-signal verification before classifying complex household incidents.

### Physical ESP32 Hardware Integration
- Validated with physical ESP32 DevKit v1 microcontrollers communicating over MQTT (QoS 1).
- Hardware acceptance tested across DHT22 (temperature/humidity), HC-SR501 PIR (occupancy), and magnetic reed switches (contact).
- Firmware features NaN cold-boot rejection, dynamic SNTP synchronization, and watchdog non-zeroing invariants.

### Fail-Closed Safety & Empirical Verification ($\Delta M$)
- Automated actions strictly gated through fail-closed safety evaluators.
- Actuation is restricted to low-voltage relays and smart plugs; mains-voltage switching is architecturally excluded.
- Post-actuation physical response is empirically verified against expected trajectories ($\Delta M$).

### Enterprise Observability & Reproducible Deployment
- Causal audit logging preserving single `correlationId`s across all 12 pipeline stages.
- In-process rolling latency percentiles ($p50/p95/p99$) and deterministic SLA-based `/api/health` checks.
- Multi-stage non-root Docker container (`node:22-alpine`), separated `/api/live` and `/api/ready` probes, baseline SQL migrations, and GitHub Actions CI.

## 4. Known Engineering Tradeoffs & UI Limitations

1. **In-Memory Single-Node State**: Sliding latency windows and rate limiters operate in process memory; horizontal clustering requires an external Redis store.
2. **Hardware Scope**: Actuation is deliberately restricted to low-voltage relays and smart plugs for physical safety.
3. **GBDT Complexity**: Model size is capped at 50 trees (depth 4) to maintain sub-10ms serverless inference budgets.
4. **Known UI Limitation (Floor Switcher)**: The Floor 1 / First Floor selector in the digital twin visualization is currently a non-functional presentation control. The underlying room telemetry, interactive room hotspots, environmental sensing, and digital-twin visualization remain fully operational.
